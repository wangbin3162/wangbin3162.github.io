# 简历素材文件路径说明

> 本文档用于说明 `assets/` 目录下全部简历素材的位置、内容与用途，便于在制作简历（网页版 / 文档版）时快速定位与引用。
> 路径均相对项目根目录 `personal/`；`【待补充】` 为素材中原有的量化占位符，使用前需按真实数据补齐。

---

```

├── projects/                     # 实际工作项目经验（13 个）
```

**命名约定**
- 每个项目 / 开源库文件夹内均有一份 `PROJECT_EXPERIENCE.md`（`13-其他项目` 与 `11-other` 为汇总式 `其他.md` / `其他开源库清单.md`），内含项目概况、背景、技术栈、角色、负责内容、优势价值与简历亮点。
- 文件夹序号（01、02…）即素材整理时的推荐优先级，序号越小越建议作为简历重点项目。
- 截图文件名以项目缩写 + 序号命名（如 `contract01.png`、`ocr02.png`），同前缀为一组。
- `.DS_Store` 为 macOS 系统文件，无内容价值，可忽略。

## 五、配套使用说明（docs 目录内既有文件）

`assets/` 为原始素材，`docs/` 下的提示词模板用于将素材转化为成稿，建议按以下顺序使用：

| 文件 | 作用 | 建议输入素材 |
| --- | --- | --- |
| [`docs/项目分析.md`](项目分析.md) | 由单个工程项目提炼 `PROJECT_EXPERIENCE.md`（已按此规范产出） | 各项目源码 / README |
| [`docs/素材整合.md`](素材整合.md) | 将全部 `PROJECT_EXPERIENCE.md` + 基础简历整合为结构化简历数据（Markdown + JSON） | 本文档第三节与第二节列出的全部路径 |
| [`docs/网页生成.md`](网页生成.md) | 依据整合结果生成单页网页版简历站点 | `素材整合.md` 输出的 JSON + `avatar.png` / `b-logo.png` / `favicon.ico` |

**引用路径速查**
- 基础信息：`assets/base/基础简历.md`
- 工作项目：`assets/projects/<序号-项目名>/PROJECT_EXPERIENCE.md` + 同目录截图
- 开源作品：`assets/github/<序号-项目名>/PROJECT_EXPERIENCE.md` + 同目录截图
- 汇总清单：`assets/projects/13-其他项目/其他.md`、`assets/github/11-other/其他开源库清单.md`

> 提示：所有 `【待补充】` 均为待量化指标，成稿前请替换为真实数据，避免简历中出现占位符。
