# 部署说明

本文档说明当前 Astro 站点的打包和部署流程。

## 1. 当前工程的真实输出

当前构建命令：

```bash
pnpm run build
```

当前构建产物目录：

```text
dist/
```

也就是说：

- 本项目现在不是把运行产物输出到 `docs/`
- 部署时应以 `dist/` 目录内容为准

## 2. 发布前准备

发布前先确认：

- 依赖已安装
- 本地开发内容已确认
- 构建能通过

安装依赖：

```bash
pnpm install
```

本地预览：

```bash
pnpm run dev
```

构建验证：

```bash
pnpm run build
```

构建完成后建议再本地预览一次产物：

```bash
pnpm run preview
```

## 3. 标准打包流程

每次准备发布时，按这个顺序做：

1. 拉取最新代码
2. 安装依赖
3. 本地检查页面
4. 执行构建
5. 检查 `dist/` 产物
6. 发布 `dist/`

常用命令顺序：

```bash
pnpm install
pnpm run build
pnpm run preview
```

## 4. 发布时要重点检查什么

当前工程已精简为仅保留首页，重点检查：

- 首页是否正常
- 备案信息和 Footer 是否正常
- 图片资源是否正常加载

## 5. 当前推荐的部署口径

因为仓库里目前没有现成的 `.github/workflows` 发布流程，所以当前文档按“发布 `dist/` 目录”来写。

推荐的部署口径：

- 如果你用 GitHub Pages：让 GitHub Pages 指向 `dist/` 对应的发布产物
- 如果你用其他静态托管：上传 `dist/` 整个目录内容

核心原则：

- 部署的不是 `src/`
- 部署的不是 `static/`
- 部署的不是旧 `docs/`
- 部署的是构建后生成的 `dist/`

## 6. 如果部署到 GitHub Pages

当前有两种常见方式。

### 方式一：手动发布 `dist/`

适合先跑通流程。

步骤：

1. 本地执行 `pnpm run build`
2. 拿到 `dist/` 目录
3. 把 `dist/` 内容发布到 GitHub Pages 对应分支或托管入口

注意：

- 具体发布到哪个分支，要看你的 Pages 配置
- 如果你还沿用旧的 `docs/` 发布方式，需要先统一策略，不要让 `docs/` 和 `dist/` 混用

### 方式二：GitHub Actions 自动发布

更适合长期维护。

推荐流程：

1. push 到主分支
2. GitHub Actions 自动安装依赖
3. 执行 `pnpm run build`
4. 将 `dist/` 发布到 GitHub Pages

当前仓库还没有这套 workflow，所以这份文档先不假设它已经存在。

## 7. 如果你继续沿用旧 `docs/` 习惯

当前工程已经逐步去掉对 `docs/` 的运行时依赖。

所以建议：

- `docs/` 只保留旧版参考资料
- 不要再把新页面开发直接写回 `docs/`
- 不要把 `docs/` 当成新的发布产物目录

如果后面你决定彻底删除 `docs/`，当前页面运行逻辑不应该受影响。

## 8. 发布失败时排查什么

### 构建失败

先检查：

- 图片路径是否正确
- 是否引用了已经删除的旧素材
- 依赖是否完整安装

### 页面打开空白

先检查：

- 部署的是不是 `dist/`
- 资源路径是不是用了错误的旧目录
- 是否构建完成后又被旧文件覆盖

### 图片丢失

先检查：

- 图片是不是已经迁入 `src/assets/`
- 部署产物里有没有对应图片
- 页面有没有继续引用 `docs/images` 或 `docs/public`

## 9. 每次上线前的最小检查清单

- `pnpm run build` 通过
- 首页可访问
- 备案信息和 Footer 正常
- 图片资源正常加载

- 本地环境差异导致的发布问题
