# Binvia 项目经验

## 项目概况
运行于 macOS 的本地 AI 供应商聚合路由网关，把 DeepSeek、CodeBuddy 等 8 家供应商收敛为一个 OpenAI 兼容端点。

## 项目背景
开发者接入多家 AI 供应商需分别维护 Key、地址与鉴权，客户端切换成本高、额度分散难管理。Binvia 用一个本地端点加一个网关 Key 屏蔽上游差异，并在菜单栏统一监控余额、请求与健康度。

## 技术栈
- 语言：Swift 6.2、macOS 14+、StrictConcurrency
- 框架：SwiftUI + AppKit、Foundation、原生 POSIX Socket
- 架构：SPM 五 Target 分层、Provider 协议注册表、SSE 流式
- 依赖：零第三方依赖，自建测试框架

## 我的角色
项目负责人 / 前端负责人，主导全模块设计与开发。

## 负责内容
- 设计 Core/UI 解耦的五 Target 分层，抽象 Provider 协议与注册表，统一 8 家上游接入
- 实现原生 Socket HTTP 服务器与路由分发，支持 Chat/Responses/Messages 三类协议
- 开发 SSE 归一化与翻译层，完成 Chat↔Responses/Anthropic 双向转换与强制流式聚合
- 构建 SwiftUI 菜单栏面板，实现启停、供应商管理与【待补充】项配置热更新
- 搭建网关 Key 鉴权、失败重试与请求监控，覆盖【待补充】量级调用统计

## 优势与价值
- 技术价值：零依赖纯 Swift 单进程兼顾代理与 GUI，数据不出本机
- 工程价值：协议化加翻译层解耦，新增供应商遵循统一范式，扩展成本可控
- 业务价值：一个端点打通多供应商，降低接入切换成本，额度状态集中可视
- 质量保障：自建测试框架覆盖路由、翻译、流式核心路径，回归稳定

## 简历亮点
- 主导五 Target 分层架构设计，以 Provider 协议与注册表统一 8 家上游，接入标准化
- 基于原生 Socket 实现本地 HTTP 网关，零第三方依赖，支持三类 API 与 SSE 流式透传
- 构建 SSE 归一化与双向翻译层，兼容 Codex、Claude Code 等客户端【待补充】种格式
- 落地配置热重载与指数退避重试，配置即改即生效，【待补充】降低中断
- 自研零依赖测试框架覆盖【待补充】项断言，保障核心链路稳定
